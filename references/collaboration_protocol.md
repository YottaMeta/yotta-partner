# 元伴协作协议单元

本文件是元伴（yotta-partner）的执行内核。它是一个可重复使用的协作协议：
上下文简报 → 方案闸门 → 分步交付 → 验证复核 → 交接与经验回流。

## 一、上下文简报模板

开始任务前，先填这份简报。缺字段时 AI 应追问，而不是猜测；用户填不全时至少要给
「目标」和「验收」，否则任务不建议直接执行。

```text
背景：
- 这件事从哪来？为什么现在做？
- 相关文件 / 系统 / 历史上下文？

目标：
- 完成态是什么？（能看见的具体结果）

约束：
- 时间：什么时候要？
- 资源：谁能做、有什么工具/权限？
- 边界：能碰哪些文件/数据/通道？不能碰什么？
- 红线：不可逆操作、外部发布、删除、授权变更等。

验收：
- 怎么算做对？（可勾选清单）
```

## 二、先方案后动手

复杂或可能产生副作用的任务，默认先出方案再执行：

1. AI 说出准备怎么做：步骤清单；
2. AI 列出会动的东西：文件、数据、外部通道、配置；
3. AI 给出验证方式：测试、回读、dry-run、人工复核；
4. AI 列出待确认问题，不等用户开口就主动问；
5. 用户批准后开始；单步低风险机械操作可先做，但要在方案里说明。

如果 AI 已经直接动手：

- 停下当前动作；
- 说明已做了什么和影响；
- 补一份方案，等用户确认后再继续。

## 三、分步交付

- 一个会话只交付一个里程碑；做完即收口，开新会话做下一件事；
- 长任务拆成小步：小步要能被检查（跑一条命令、读一个输出、看一个文件）；
- 每完成一个可检查步骤，简短汇报结果，不等到最后才说；
- 不连续堆任务；上下文变长时先把关键状态落盘，再继续。

## 四、验证复核清单

交付前逐条自检：

- [ ] 验收标准逐条满足，不是笼统说「完成了」；
- [ ] 关键结论可溯源：代码 / 命令 / 日志 / 引用 / 截图？
- [ ] 测试、校验、dry-run 已运行，且输出已核对；
- [ ] 没有越权动作：未批准的文件写、删除、推送、发布；
- [ ] 不确定的地方如实标注，没有把猜测写成事实；
- [ ] 若任务跨会话，已更新状态并留下交接锚点。

用户复核时，可以只做三件事：

1. 看验收清单是否真过；
2. 抽样看不理解的关键结论，要求给证据；
3. 对高风险动作要求 AI 先 dry-run 或回滚方案。

## 五、交接锚点模板

跨会话任务结束时，输出一段自包含交接锚点。新会话只凭这段文字就能接续：

```markdown
【会话交接锚点】
项目：项目名（一句话定位）
路径：项目根目录绝对路径

上次会话结束于：YYYY-MM-DD

当前进度：
- 做到哪一步

已完成：
- 已完成的关键结果

下一步（按优先级）：
1. 下一件事
2. 再下一件事

关键决定（详情见状态文件）：
- 影响方向的决定及理由

遗留问题 / 注意：
- 未解决项、风险、待确认

开工请先读取：状态文件路径
```

状态文件不一定叫 `.workflow`；以项目自己的约定为准，但必须给出明确路径。

## 六、经验回流

- 有效做法、踩坑原因、修复方法，先写进项目内日志或 `.learnings/`；
- 若已安装元习（yotta-learn），用它的条目协议沉淀，格式统一可检索；
- 若已安装元忆（yotta-memory），重要事实用 `remember` 落盘，边界/偏好用私密类型；
- 涉及用户隐私或敏感信息时，先获得用户同意再记录；
- 沉淀不是攒文本：每条要能回答「当时发生什么 / 为什么 / 下次怎么办」。

## 七、边界

- 本协议只处理协作方法和交付纪律，不做领域决策；
- 不读用户数据、不自动收集隐私；记录范围由用户同意；
- 不保证 AI 输出正确，最终复核责任在用户；
- 不含商业、定价、运营、获客话题。
